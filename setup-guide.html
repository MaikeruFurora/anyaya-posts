00 Paano gumagana

Anim na step. Isa lang yung sayo.

01 GitHub repo — dito gagawin yung images

Dito ire-render yung images, at dito rin ito naka-host.

Gumawa ka ng bagong public repo — wag mong gamitin yung flow repo ng website mo para walang masira doon. Tawagin nating anyaya-posts.

  1. Gumawa ng public repo: anyaya-posts
  2. I-upload yung mga file galing sa zip:
    • render.js, template.html, fonts.css, package.json, package-lock.json — pwede sa root
    • .github/workflows/render-post.yml — dito nakalagay yung instructions kung paano gagawin yung image
    • docs/posts/ — empty folder kung saan mapupunta yung mga image. Lagyan mo ng .gitkeep para tanggapin ng Git.
  3. Settings → Pages → Source: Deploy from a branch, branch main, folder /docs. Save.
  4. Settings → Actions → General → Workflow permissions: piliin yung Read and write permissions. Kailangan ito para maka-commit yung bot ng mga image.
Tandaan: nasaan yung files?

Kung nasa root ng repo yung render.js at hindi sa loob ng render/ folder, siguraduhin mong walang working-directory: render sa workflow YAML mo. Kung mali ang path, "file not found" ang lalabas at hindi ka makakapag-render.

Personal access token

Ito yung gagamitin ng n8n para sabihan yung GitHub na mag-generate ng image. Hindi ito yung render/ folder — ibang bagay yun.

Settings → Developer settings → Personal access tokens → Fine-grained tokens. Piliin lang yung anyaya-posts repo, tapos bigyan mo ng Contents: Read and write at Metadata: Read. Copy mo yung token — yan yung GH_TOKEN.

Bakit public yung repo

Dalawang dahilan: libre yung GitHub Actions minutes sa public repo, at kailangang mabasa ng Meta yung image nang walang password. Walang secret na nakalagay dito — mga larawan lang na ipopost mo rin naman.

02 Gemini API key — yung writer

Libre, walang credit card, at isang request lang gamit mo per day.

Punta ka sa aistudio.google.com/apikey, mag-sign in, tapos pindutin yung Create API key. Copy mo — yan yung GEMINI_API_KEY.

Yung free tier ng gemini-2.5-flash ay 1,500 request per day at 15 per minute. Isa lang kailangan mo kada araw, kaya sobrang layo mo pa sa limit kahit mag-retry ka pa nang ilang beses.

Heads up

Sa free tier, pwedeng gamitin ng Google yung pinapadala mo para i-improve yung models nila. Walang client data na dumadaan dito — marketing copy lang — pero mabuting alam mo.

03 Render + Supabase — dito tatakbo yung n8n

Walang credit card kahit saan dito.

Binibigyan ka ng Render ng libreng HTTPS URL, kaya hindi ka na kailangang bumili ng domain at gagana yung mga button sa email mo.

Dalawang kahinaan, dalawang solusyon

Natutulog yung Render pag 15 minutong walang traffic. Ibig sabihin hindi maaasahan yung cron sa loob ng n8n — kaya GitHub Actions yung tatawag dito ng 6 AM.
Nabubura yung disk pag nag-restart. Kaya sa Supabase Postgres naka-save yung workflows at credentials mo, hindi sa Render.

3A · Supabase — yung database

  1. Mag-signup sa supabase.com gamit yung GitHub account mo. Walang card.
  2. New project. Region: Southeast Asia (Singapore). Gumawa ng malakas na database password at i-copy mo agad — isang beses lang ito ipapakita.
  3. Pag ready na, pindutin yung berdeng Connect button sa taas ng project page.
  4. Hanapin mo yung Session pooler — hindi Direct, hindi Transaction. Ganito ang itsura:
postgresql://postgres.PROJECTREF:[PASSWORD]@aws-X-ap-southeast-1.pooler.supabase.com:5432/postgres
             └──────── user ────────┘        └──────────── host ─────────────┘
Wag mong gamitin yung Direct connection

Yung db.PROJECTREF.supabase.co ay IPv6 lang sa free plan, tapos IPv4 lang kayang lumabas ng Render. Mag-e-error ito ng ENETUNREACH. Session pooler lang ang gagana.

3B · Render — yung n8n

  1. Mag-signup sa render.com gamit yung GitHub.
  2. New → Web Service → Existing Image. Ilagay mo: n8nio/n8n:2.35.3
  3. Instance type: Free. Region: Singapore.
  4. Ilagay yung mga environment variable sa baba, tapos Deploy.
Docker Hub, hindi yung registry ng n8n

Kung docker.n8n.io/n8nio/n8n ang ilagay mo, sasabihin ng Render na "No public image found." Hindi nito kayang basahin yung sariling registry ng n8n — Docker Hub lang. Kaya n8nio/n8n ang tamang pangalan. Naka-pin sa 2.35.3 para walang biglaang update na makakasira sa workflow mo habang tulog ka.

Para gumawa ng dalawang random secret:

openssl rand -hex 24    # para sa N8N_ENCRYPTION_KEY
openssl rand -hex 32    # para sa TRIGGER_SECRET
Hindi mo pa alam yung WEBHOOK_URL sa simula

I-deploy mo muna kahit wala ito. Pag lumabas na yung URL mo — halimbawa https://anyaya-n8n.onrender.com — balikan mo yung Environment, idagdag mo, tapos redeploy. Kung mali ito, magiging localhost yung approve link sa email mo at hindi gagana.

Paano malalaman kung gumana

Sa Logs tab ng Render, ito ang hanapin mo:

Editor is now accessible via: https://....onrender.com

Pangalawang check: sa Supabase, punta ka sa Table Editor. Kung nakakonekta talaga yung n8n, may mga 20+ table na siyang ginawa doon. Kung walang laman, hindi pa ito nakakakonekta.

3C · Yung alarm clock

Sa GitHub repo mo, punta ka sa Settings → Secrets and variables → Actions, tapos gumawa ng dalawang repository secret:

TRIGGER_SECRETKaparehas ng nasa Render
N8N_WEBHOOK_URLhttps://…onrender.com/webhook/anyaya-daily-post

Nasa zip yung daily-trigger.yml. Ilagay mo sa .github/workflows/ ng repo mo. Ito yung gigising sa n8n ng 22:00 UTC — 6 AM sa Manila.

Mga dapat mong asahan

Mga isang minuto bago gumising yung Render, kaya may tatlong retry yung alarm clock bago sumuko. Nagpa-pause yung Supabase free database pag isang linggong walang activity — hindi ito mangyayari kung araw-araw kang nagpo-post. Tapos minsan nade-delay yung GitHub cron ng hanggang 30 minuto pag maraming gumagamit.

04 Meta tokens — yung pinakamahirap

Isang beses lang ito, pero isang upo. Mga 30 minuto.

Bago ka magsimula

  • Dapat Business o Creator account yung Instagram mo, hindi Personal.
  • Dapat naka-link yung IG sa Facebook Page mo (Page Settings → Linked accounts).

Mga steps

  1. Sa developers.facebook.com/apps, gumawa ng app na Business type.
  2. Idagdag yung Facebook Login for Business at Instagram products.
  3. Buksan yung Graph API Explorer. Piliin yung app mo, tapos Get Page Access Token, tapos piliin yung Anyaya Designs Page.
  4. Hingin mo itong mga permission: pages_manage_posts, pages_read_engagement, pages_show_list, instagram_basic, instagram_content_publish, business_management
  5. Kunin yung Page ID: i-run yung me/accounts sa Explorer.
  6. Kunin yung IG User ID: i-run yung {page-id}?fields=instagram_business_account

Gawing hindi mag-e-expire yung token

Yung token galing sa Explorer ay 1–2 oras lang. Palitan mo ito ng long-lived user token, tapos doon mo kunin yung page token — yung page token na galing sa long-lived user token ay hindi nag-e-expire. 

# 1. short-lived user token → long-lived user token (60 days)
curl -s "https://graph.facebook.com/v23.0/oauth/access_token\
?grant_type=fb_exchange_token\
&client_id=APP_ID\
&client_secret=APP_SECRET\
&fb_exchange_token=SHORT_LIVED_TOKEN"

# 2. long-lived user token → page token (walang expiry)
curl -s "https://graph.facebook.com/v23.0/me/accounts\
?access_token=LONG_LIVED_USER_TOKEN"

I-verify mo sa Access Token Debugger na Never yung nakalagay sa Expires. Yan yung FB_PAGE_TOKEN.

Graph API version

Mga 2 taon lang buhay ng bawat version. Naka-set ito sa FB_API_VERSION kaya isang lugar lang papalitan mo. Check mo yung changelog kung ano yung pinakabago bago ka magsimula.

05 Email para sa approval

Gmail SMTP, app password ang gamit — hindi yung totoong password mo.

  1. I-on yung 2-Step Verification sa Google account mo.
  2. Punta sa myaccount.google.com/apppasswords tapos gumawa ng app password para sa "n8n".
  3. Sa n8n: Credentials → New → SMTP. Host smtp.gmail.com, port 465, SSL on, user yung Gmail mo, password yung app password.

Pangalanan mong Anyaya SMTP tapos piliin mo ito sa Email: pa-approve node.

Normal na mabagal yung unang tawag

Natutulog yung Render, kaya mga isang minuto bago ito gumising sa unang subok. May tatlong retry yung alarm clock — wag kang mag-alala kung "Subok 2" ang nakita mo sa log.

Kung na-fail yung Instagram pero pumasa yung Facebook

Halos palaging ibig sabihin nito: hindi pa Business account yung IG, hindi naka-link sa Page, o hindi pa approved yung instagram_content_publish. Hindi ito problema sa image — nakuha na nga yun ng Facebook.

08 Yung araw-araw mong gagawin

Mga sampung segundo.

6 AM, may darating na email. May larawan, may caption, at dalawang button. Tingnan mo kung ok yung dating — kung oo, pindot I-post na. Live na ito sa Facebook at Instagram sa loob ng ilang segundo.

Kung ayaw mo, pindutin yung Huwag, o pabayaan mo lang — mag-e-expire ito after 12 oras at walang mapopost.

May naka-set na topic kada araw: Lunes problema, Martes at Sabado tips, Miyerkules product, Huwebes sagot sa mga alinlangan, Biyernes tanong sa audience, Linggo naman offer. May 56 na magkakaibang angle bago pa mag-ulit — mahigit dalawang buwan.

09 Maintenance at pagbabago

Mga bagay na masisira balang-araw, at paano ayusin.

Pag nag-start mag-fail yung posting

  • Nag-e-expire yung Graph API version mga every 2 years. Palitan mo lang yung FB_API_VERSION.
  • Na-void yung page token pag pinalitan mo yung password mo o binawi yung app permissions. Ulitin mo yung step 04.
  • Nag-pause yung Supabase pag isang linggong walang activity. Hindi ito mangyayari kung araw-araw kang nagpo-post.
  • Hindi gumising yung Render. Check mo yung logs ng Daily post trigger sa GitHub — doon lalabas kung 200 o hindi.

Pag gusto mong baguhin yung sinasabi ng posts

Nasa dalawang lugar lang lahat, parehas nasa anyaya-daily-post.json:

  • Pumili ng pillar at angle node — dito yung listahan ng 56 topics. Pwede kang magdagdag, magbura, o magpalit. Deterministic yung pagpili kaya alam mo kung kailan lalabas ang bawat isa.
  • Gemini: sumulat ng post node — dito yung tono, yung mga bawal na salita, at yung caption formula.

Pag gusto mong baguhin yung itsura

Nasa template.html lahat ng design. Nasa taas yung mga kulay bilang CSS variables — palitan mo yung --sage at --kraft tapos magbabago lahat ng post. I-run mo yung npm run samples para makita yung bagong itsura nang hindi ginagalaw yung buong system.

Pag gusto mong magdagdag ng bagong hitsura ng post

Pito yung variants: quote, tips, stat, compare, question, feature, cta. Para magdagdag: gumawa ng bagong CSS block sa template.html, idagdag sa switch sa script, banggitin sa system prompt, tapos ilagay sa VARIANTS ng render.js.

May kasamang test

I-run mo yung node n8n/test-logic.js tuwing may binago ka. Sinusuri nito yung 56-day rotation, yung mga guardrail laban sa gawa-gawang presyo at testimonial, tapos nirerender lahat ng pitong variant nang totohanan — hindi lang sinusubukan, ginagawa talaga.
